# Assumptions

## Money
- Amounts and balances are integer paise in requests and responses (`15000` = ₹150.00).
- Decimal amounts (`100.50`) and numeric strings (`"100"`) are rejected with 400.
- The largest accepted amount is `Number.MAX_SAFE_INTEGER` paise. Amounts are stored as `BIGINT` and returned as JSON numbers.

## Accounts
- Account and transaction ids are UUIDs generated by the server.
- A malformed id returns 400 `VALIDATION_ERROR`. A well-formed id with no account returns 404 `ACCOUNT_NOT_FOUND`.
- `name` is trimmed and stored trimmed. A whitespace-only name counts as missing (400).
- There are no endpoints to update or delete accounts, because the spec doesn't ask for them.

## Transactions
- `description` is optional. When omitted it is stored and returned as `null`.
- `reference_id` is trimmed and stored trimmed, so `" REF1"` and `"REF1"` are the same reference. A whitespace-only `reference_id` counts as missing (400).
- A duplicate `reference_id` on the same account returns 409 `DUPLICATE_REFERENCE` with the original transaction, even if the amount or type differ.
- The duplicate check runs before the balance check, so retrying a debit that already succeeded returns 409, not 422.
- Insufficient balance returns 422 `INSUFFICIENT_BALANCE`.
- PUT, PATCH and DELETE on transactions return 404 `NOT_FOUND`, because no such routes exist. 405 was considered and not used.

## Transaction history
- `page` defaults to 1 and `limit` defaults to 10. `limit` is at most 100.
- A page past the last page returns 200 with empty `data`.
- Transactions with the same `created_at` are returned in reverse insertion order, so latest-first is stable.
- Unknown query parameters (for example `?foo=1`) return 400, the same as unknown body fields.

## Transfers
- A transfer creates two transactions that share the transfer's `reference_id`: a debit on the source and a credit on the destination.
- If either account already has that `reference_id`, the transfer returns 409 with the existing transactions.
- A transfer to the same account returns 400.
- If an account is missing, the 404 names it in `details.account_id`.

## Errors
- Malformed JSON returns 400 `VALIDATION_ERROR` with message `Invalid request` and the parser's message in `details`.
- Unexpected errors return 500 `INTERNAL_ERROR` without a stack trace or database message. The full error is logged on the server.

## Scope
- The spec has no section 6, so nothing is assumed for it.
- There is no authentication.
